# 影视资源站 XML 采集接口 参数说明

> **依据**：该接口族的标准实现（采集控制器 `vod` 动作与 XML 输出方法）、官方接口说明文档、后台默认配置。
> **实测样本**：巨浪（新版部署）、芒果（旧版部署）——仅以名称指代，不记录其地址。
> **实测时间**：2026-11-16，请求头与项目一致（Chrome UA、`Accept-Language: zh-CN`、`Cache-Control: max-age=0`）。
> **阅读约定**：参数语义以官方设计为准；实测列写作 `巨浪 / 芒果`，✅ = 该站生效，⚠️ = 官方有但该站未生效。
> 文中所有接口地址均写作 `{base}`（站点提供的采集入口），不含任何第三方站点地址。

---

## 一、接口定位

| 项 | 值 |
|---|---|
| 接口性质 | 影视资源**采集接口**（资源站对外提供的标准抓取接口），供聚合端 / App 拉取数据；不是前台 REST API |
| 入口 | 站点提供的采集地址 `{base}`，视频模块即视频采集入口 |
| 动作 | 由 `ac` 决定：`list` = 列表 + 分类；`detail` = 详情（整页全字段） |
| 输出格式 | 默认 JSON；**`at=xml` 时输出 XML**（RSS 5.1 外壳） |
| `at` 的两种写法 | 路径段：`{base}/at/xml/?ac=list`；查询参数：`{base}/?ac=list&at=xml`（实测两者等价） |
| 方法 | GET |
| 排序 | 固定按 `vod_time` 排序，方向由 `sort_direction` 控制（默认 `desc`） |
| 分页 | 默认每页取后台配置 `api.vod.pagesize`（默认 **20**），可用 `pagesize` 覆盖，**上限 100** |
| 缓存 | 后台配置 `api.vod.cachetime > 0` 时，按“全部参数”的 md5 缓存整段输出，参数变即换 key |
| 全局开关 | `api.vod.status != 1` → 直接输出纯文本 `closed`；`api.vod.charge = 1` → 走 IP/域名白名单鉴权 |

官方实现要点：进入 `vod` 动作先判开关与鉴权，再拼查询条件、分页与排序，最后按 `at` 分支输出 XML 或 JSON。

## 二、参数总表（官方全量 12 个）

| # | 参数 | 取值 / 格式 | 默认 | 作用 | 实测（巨浪 / 芒果） |
|---|---|---|---|---|---|
| 1 | `ac` | `list` \| `detail` \| `videolist` | 无（缺省按列表处理） | 模式：列表 / 详情（`videolist` 为历史别名） | ✅ / ✅ |
| 2 | `ids` | 逗号分隔的 vod_id，如 `1,2,3` | 无 | 指定视频 ID 集合，列表/详情模式都可用 | ✅ / ✅ |
| 3 | `t` | 单个分类 ID | 无 | 按分类过滤（受 `typefilter` 限制） | ✅ / ✅ |
| 4 | `wd` | 任意 UTF-8 文本 | 无 | 片名模糊搜索 `vod_name LIKE %wd%` | ✅ / ✅ |
| 5 | `pg` | 正整数，从 1 开始 | `1` | 页码 | ✅ / ✅ |
| 6 | `h` | 正整数（小时） | 无 | 只取最近 N 小时更新的数据 | ✅ / ✅ |
| 7 | `year` | `2026` 或 `2005-2010` | 无 | 按年份 / 年份区间过滤 | ✅ / ⚠️ |
| 8 | `isend` | `1` \| `0` | 无 | `1` 只看已完结，`0` 只看未完结 | ✅ / ⚠️ |
| 9 | `from` | 播放器组名，如 `m3u8`（可逗号多值） | 取配置 `api.vod.from` | 限定播放线路，影响 `<dt>` 与 `<dl>` | ✅ / ✅ |

| 11 | `sort_direction` | `asc` \| `desc` | `desc` | 按更新时间排序方向（仅认 `asc`） | ✅ / ⚠️ |
| 12 | `at` | `xml` \| 其它 | JSON | 输出格式开关 | ✅ / ✅ |

> 另有 4 项**服务端配置**会影响返回结果（不是请求参数）：`typefilter`、`datafilter`、`charge/auth`、`cachetime`，见第三节末尾。

## 三、参数详解（按官方实现）

### 1. `ac` — 模式（列表 / 详情）

| 取值 | 行为 | 输出差异 |
|---|---|---|
| `list` | 列表模式 | `<video>` 只含 `last / id / tid / name / type / dt / note`；**不返回 `pic`、不返回 `dl`**；末尾附带 `<class>` 分类列表 |
| `detail` | 详情模式 | `<video>` 含全字段：`pic / lang / area / year / state / note / actor / director / dl / des`；**不输出 `<class>`** |
| `videolist` | 历史别名，与 `detail` 完全等价 | 同上 |

官方判断逻辑：`ac` 等于 `videolist` 或 `detail` 时走“详情模式”（全字段），否则走“列表模式”（精简字段 + 分类列表）。

要点：

- **`detail` 不是“只能按 id 查一条”**：`ac=detail&pg=1&t=59` 会返回该分类第 1 页的 20 条**完整数据**（含封面与播放地址）。这是官方设计里“一次请求拿全列表”的方式。
- 实测：`?ac=detail&pg=1` → 20 条、20 个 `<pic>`、40 个 `<dd>`、142,761 B；`?ac=detail&t=59&pg=1` → 20 条、145,477 B。
- `ac` 缺省时官方代码未做存在性判断，实际按列表模式走；请求时建议始终显式传 `ac`。

### 2. `ids` — 指定视频 ID

- 官方逻辑：`ids` 非空时直接作为 `vod_id IN (…)` 条件。
- **与 `ac` 无关**：`ac=list&ids=1,2` 也生效（返回这 2 条的列表字段）。实测 `?ac=list&ids=66956,66954` → `recordcount=2`、2 条。
- 多值用英文逗号 `,`；不做数量上限校验（受 SQL `IN` 长度与 PHP 内存限制）。
- **空值等于不过滤**：官方用“非空判断”，所以 `?ids=` 不会筛出空集，而是退化成“返回第一页整页”（实测 138,713 B）。
- 抓取侧应判空，避免无意义的大响应。
- 附：仅当 `ac=detail` **且** `ids` 为单个纯数字、且后台开启 `detail_inc_hits` 时，官方会给该片浏览量 +1。

### 3. `t` — 分类过滤

官方判断顺序是“先按后台 `typefilter` 限制范围，再判断 `t`”：

```php
if (!empty($this->_param['t'])) {
    if (empty($config['typefilter']) || strpos($config['typefilter'], $this->_param['t']) !== false) {
        $where['type_id'] = $this->_param['t'];
    }
}
```

- 语义：**若 `typefilter` 已配置且 `t` 不在其中，`t` 被静默忽略**（返回的是 typefilter 允许的全部分类）。
- 判断用的是 `strpos` **子串匹配**：`typefilter="1,11"` 时传 `t=1` 会命中，`t=2` 不会——属于官方实现的宽松（甚至可误判）行为，接入时按站点实配理解即可。
- 只支持**单个**分类 id；`t=1,2` 会被当成字符串做等值比较，等于查不到。
- 分类 id 必须取自同一接口 `ac=list` 返回的 `<class><ty id="…">`。
- 实测芒果：55 个分类，id 覆盖 20–82；`t=59` → 1,136 条 / 57 页；`t=51` → 2,604 条 / 131 页；不存在的 `t=999999` → 200 + 空列表（官方不报 404；个别站点会自行实现成 404）。

### 4. `wd` — 关键词搜索

- 官方逻辑：`vod_name LIKE %wd%`。
- **只搜片名**（`vod_name`），不搜演员、导演、简介、标签。
- 空值不过滤（非空判断），因此 `wd=` 等价于“不带关键词”。
- 所有入参统一经过 `trim + urldecode`：这意味着 `wd` 里的 `%xx` 会被解码一次，客户端只需编码一次，**不要双重编码**。
- 实测芒果：`wd=冰箱`（原始中文，客户端编码后）→ 5 条；`wd=%E5%86%B0%E7%AE%B1`（预编码）→ 同样 5 条；`wd=总裁` → 133 条 / 7 页；`wd=恋爱` → 456 条 / 23 页；无结果 → 200 + `pagecount=0`。

### 5. `pg` — 页码

- 官方逻辑：`pg` 为空（`0`、空串、未传）时归一化为 1。
- 从 **1** 开始；实测 `pg=0` 返回 `page="1"`。
- **负数不做校验**，直接进 SQL `LIMIT` 偏移，可能报错或行为异常 → 抓取侧只传正整数。
- 超出总页数不报错：返回 `page` 原值 + 空 `<list>`（实测 `pg=99999` → 200，`videos=0`）。
- 总页数 = `pagecount`，总条数 = `recordcount`，实际每页条数 = `pagesize`（都在 `<list>` 属性上）。

### 6. `h` — 最近 N 小时更新

官方逻辑（等价代码）：

```php
$tommdate = date('Y-m-d H:i:s', strtotime('-' . $h . ' hours'));
$where['vod_time'] = [['gt', strtotime($tommdate)], ['lt', strtotime('明天0点')]];
```

- 即 `vod_time ∈ (now - h 小时, 明天 0 点)`；配合 `pg` 可翻最近更新的多页。
- 典型用法：`{base}/at/xml/?ac=detail&h=24&pg=1`。
- 实测：芒果 `h=24` → 793 条 / 40 页、`h=1` → 10 条；巨浪 `h=24` → 665 条 / 34 页。
- 抓取侧注意：`h` 会被字符串拼进时间表达式，务必传纯数字。

### 7. `year` — 年份过滤

官方逻辑：

- 长度 **4**：单个年份，如 `year=2026`；
- 长度 **9**：区间，格式必须是 `起始-结束`，如 `year=2005-2010`（第 5 位是分隔符）；内部会展开成逗号列表，并夹取 `[1900, 今年+3]`；
- **其它长度不处理**（变量未定义，PHP 8 下会告警，过滤条件异常）→ 只传这两种格式。
- 实测：巨浪 `year=2026` → 59,415 条；`year=2019` → 8,267 条，均生效；芒果未生效（返回与不带相同，部署版本较早）。

### 8. `isend` — 是否完结

- 官方用 `isset()` 判断，**只要出现该参数就生效**：`isend=1` → 已完结；任何非 `1` 的值（含 `0`）→ 未完结。
- 实测：巨浪生效——`isend=1`（已完结）212,254 条、`isend=0`（连载中）140,991 条，两者相加 ≈ 全量 353,245 条；芒果未生效（`isend=1` 与 `isend=0` 结果与不带一致）。
- 抓取侧注意：想“不过滤”就不要带这个参数，而不是传 `isend=`。

### 9. `from` — 播放线路过滤

- 官方逻辑：仅当后台配置 `api.vod.from` 为空、且参数长度 ≥ 2 时才生效；用 `vod_play_from LIKE %from%` 过滤，因此是**包含匹配**（`from=m3u8` 也会命中 `ffm3u8` 之类的组名）；支持逗号多值，如 `from=m3u8,mgtv`。
- 影响：
  - 列表模式 `<dt>` 只输出该线路名（实测芒果 `from=m3u8` → `<dt>m3u8</dt>`）；
  - 详情模式 `<dl>` 只输出匹配到的 `<dd>`（实测 `?ac=detail&ids=…&from=m3u8` 只返回 `m3u8` 组）。
- 注意：这与“路径式线路过滤”（在 `{base}` 后追加 `/from/<组名>/`，再接 `/at/xml/`）是同一套机制的不同入口，效果等价。

### 10. `pagesize` — 每页条数

- 官方逻辑：默认取配置 `pagesize`（默认 20）；参数 > 0 时取 `min(pagesize, 100)`。
- 响应 `<list pagesize="N">`（XML）或 `"limit":N`（JSON）即实际生效值。
- **该参数确实受支持，只是不同站点版本表现不同**：

| 请求 | 巨浪（新版） | 芒果（旧版） |
|---|---|---|
| `pagesize=10` | ✅ `limit=10` / `<list pagesize="10">`，10 条 | ⚠️ 仍 20 条 |
| `pagesize=50` | ✅ 50 条，71,593 B（JSON） | ⚠️ 仍 20 条 |
| `pagesize=200` | ✅ **被封顶为 100**（官方 `min(…,100)` 生效） | ⚠️ 仍 20 条 |

- 例（巨浪，JSON）：`{base}?ac=detail&at=json&pagesize=10` → `"limit":10`、10 条、`"pagecount"` 随之从 17,663 变为 35,325。
- 结论：**`pagesize` 是官方参数且新版部署确实生效**；旧版部署（如芒果）会静默忽略。抓取侧应“请求后回读 `pagesize/limit` 校验是否生效”，而不是假定生效。
- 抓取侧价值：一次 20 条提升到 50/100 条可显著减少请求数与总耗时（注意单页响应体积同步变大，100 条的详情页可达 500 KB 级）。

### 11. `sort_direction` — 排序方向

- 官方逻辑：只有 `asc` 被识别，其它一律 `desc`；排序字段固定 `vod_time`，不支持自定义排序字段。
- 实测：巨浪生效（`asc` 时首条为最旧的 `2026-08-02 18:15:37`）；芒果未生效（`asc` 与默认首条相同）。

### 12. `at` — 输出格式

- 官方逻辑：`at=xml` → XML；否则 JSON。
- 两种写法实测均可用：
  - 路径：`{base}/at/xml/?ac=list` → XML（4,734 B）
  - 查询：`{base}/?ac=list&at=xml` → XML（4,736 B）
  - 不带：`{base}/?ac=list` → JSON（5,825 B）
- 抓取侧建议固定用路径式（与多数资源站给出的采集地址一致），可避免参数丢失。

### 附：影响输出的 5 项服务端配置

| 配置项 | 默认值 | 作用 |
|---|---|---|
| `api.vod.status` | `1` | 非 1 时直接输出纯文本 `closed`（不是 XML，解析会失败） |
| `api.vod.charge` + `auth` | `0` / 空 | 开启后按客户端 IP 白名单校验（白名单 = `127.0.0.1` + `#` 分隔的域名解析结果），不在名单输出鉴权错误文本 |
| `api.vod.typefilter` | 空 | 限定可对外提供的分类；同时影响 `<class>` 列表与 `t` 是否生效 |
| `api.vod.datafilter` | ` vod_status=1` | 追加原生 SQL 条件；输出前还会把 `{: / <script / <iframe / <frameset / <object / onerror` 替换为 `*`（影响 `des` 里的 HTML） |
| `api.vod.cachetime` | 空 | >0 时按参数 md5 缓存整段响应 |

## 四、URL 用法示例

> `{base}` = 站点提供的采集入口；XML 形态在末尾加 `/at/xml/`。

```text
# 官方文档示例
?ac=list                                  列表
?ac=detail                                详情（整页全字段）
?ac=list&t=1&pg=5                         分类 1 的第 5 页
?ac=detail&ids=123,567                    指定 ID 批量详情
?ac=detail&h=24                           24 小时内更新的详情

# 其余按官方实现支持的组合
?ac=list&wd=总裁&pg=1&t=59                 分类内搜索（wd 与 t 同时生效，AND）
?ac=list&pagesize=50&pg=2                 每页 50 条（站点需支持）
?ac=list&sort_direction=asc               按更新时间正序
?ac=list&year=2026                        2026 年
?ac=list&year=2005-2010                   2005–2010 区间
?ac=list&isend=1                          只看已完结
?ac=list&from=m3u8                        只看 m3u8 线路
?ac=detail&t=59&pg=1&from=m3u8            一次取整页完整数据（含封面/m3u8）
```

XML 形态（实测数据）：

| 请求 | 状态 | 体积 | 条数 |
|---|---|---|---|
| `?ac=list` | 200 | 4,734 B | 20 + 55 个分类 |
| `?ac=list&pg=2` | 200 | 4,719 B | 20 |
| `?ac=list&wd=总裁&pg=1&t=59` | 200 | 3,194 B | 11 |
| `?ac=list&h=24` | 200 | — | 793 条 / 40 页 |
| `?ac=list&ids=66956,66954` | 200 | — | 2 |
| `?ac=detail&ids=66956` | 200 | 9,006 B | 1（2 个 `<dd>`，m3u8 81 集） |
| `?ac=detail&ids=1,2,3` | 200 | 31,198 B | 3 |
| `?ac=detail&ids={20 个}` | 200 | 138,707 B | 20 |
| `?ac=detail&pg=1` | 200 | 142,761 B | 20（含 pic + dl） |

## 五、返回结构（按官方 XML 输出）

### 5.1 外层

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="5.1">
  <list page="1" pagecount="4479" pagesize="20" recordcount="89564"> … </list>
  <class> … </class>   <!-- 仅列表模式 -->
</rss>
```

**4 个分页字段全部是 `<list>` 的属性**：

```php
$xml .= '<list page="'.$res['page'].'" pagecount="'.$res['pagecount']
      . '" pagesize="'.$res['limit'].'" recordcount="'.$res['total'].'">';
```

### 5.2 `<video>` 字段（两种模式不同）

| 字段 | 列表模式（`ac=list`） | 详情模式（`ac=detail` / `videolist`） | 说明 |
|---|---|---|---|
| `last` | ✔ | ✔ | `vod_time` 格式化 `Y-m-d H:i:s` |
| `id` | ✔ | ✔ | `vod_id` |
| `tid` | ✔ | ✔ | `type_id` |
| `name` | ✔ CDATA | ✔ CDATA | `vod_name` |
| `type` | ✔ | ✔ | 分类名（由 `type_id` 查缓存映射） |
| `dt` | ✔ | ✘ | 可用播放器组：配置 `from` 非空时输出该值，否则 `vod_play_from` 用 `,` 连接 |
| `pic` | ✘ | ✔ | 封面；`mac:` 前缀与相对路径会被补全为绝对 URL |
| `lang` / `area` / `year` | ✘ | ✔ | 语言 / 地区 / 年份 |
| `state` | ✘ | ✔ | `vod_serial`（集数/连载状态） |
| `note` | ✔ CDATA | ✔ CDATA | `vod_remarks` |
| `actor` / `director` | ✘ | ✔ CDATA | 主演 / 导演 |
| `dl` | ✘ | ✔ | 播放地址，见 5.4 |
| `des` | ✘ | ✔ CDATA | 简介（HTML 已被过滤替换） |

字段生成顺序：`last → id → tid → name → type → [pic → lang → area → year → state → note → actor → director → dl → des]` 或 `[dt → note]`。

### 5.3 `<class>` 分类（仅列表模式）

```xml
<class><ty id="20">电影片</ty><ty id="21">连续剧</ty>…</class>
```

- 只输出 `type_mid == 1`（视频）的分类；
- `id` 是**属性**；配置了 `typefilter` 时只列出被允许的分类。

### 5.4 `<dl>` / `<dd>` 播放地址

```xml
<dl>
  <dd flag="m3u8"><![CDATA[第1集$https://<CDN域名>/xx/index.m3u8#第2集$https://<CDN域名>/xx/index.m3u8]]></dd>
  <dd flag="mgtv"><![CDATA[第1集$https://<CDN域名>/share/xxx#…]]></dd>
</dl>
```

官方生成逻辑：

1. 站点把 `vod_play_from`、`vod_play_url` 都按 `$$$` 分隔成多组；
2. 每组输出一个 `<dd flag="组名">`，内容为组内 `vod_play_url` 原文；
3. `flag` 是**属性**；
4. 组内文本的 `第1集$url#第2集$url` 是站点数据侧约定（`#` 分集、`$` 标题与地址分隔），官方**原样输出、不做解析**。

所以抓取侧需要自己按 `#` / `$` 拆分，并以 `.m3u8` 判断可播线路。

## 六、实测支持矩阵（两个真实站点）

同一份官方代码，**不同部署的参数支持面差别很大**：巨浪（新版）几乎全支持，芒果（旧版）只支持 8 个。

| 参数 | 官方 | 巨浪（新版） | 芒果（旧版） |
|---|---|---|---|
| `ac` | ✅ | ✅ `list` / `detail` / `videolist` | ✅ 同左（55 个分类，id 20–82） |
| `ids` | ✅ | ✅ 列表模式也生效（传 2 个 id → 2 条） | ✅ 同左 |
| `t` | ✅ | ✅ | ✅ `t=59`→1,136 条、`t=51`→2,604 条 |
| `wd` | ✅ | ✅ | ✅ `wd=总裁`→133 条、`wd=恋爱`→456 条 |
| `pg` | ✅ | ✅ | ✅ 1 起，越界返回空 |
| `h` | ✅ | ✅ `h=24`→665 条 / 34 页 | ✅ `h=24`→793 条 / 40 页、`h=1`→10 条 |
| `year` | ✅ | ✅ `2026`→59,415 条、`2019`→8,267 条 | ⚠️ 无效果 |
| `isend` | ✅ | ✅ 已完结 212,254 + 连载 140,991 ≈ 全量 | ⚠️ 无效果 |
| `from` | ✅ | ✅ `from=<m3u8线路>` → `<dt>` 只剩该线路 | ✅ `from=<m3u8线路>` → `<dt>` 只剩该线路 |
| `pagesize` | ✅ | ✅ 10 / 50 生效，200 被封顶 100 | ⚠️ 恒为 20 |
| `sort_direction` | ✅ | ✅ `asc` 时首条回到 2026-08-02 | ⚠️ 无效果 |
| `at` | ✅ | ✅ 路径式 + 查询式 | ✅ 路径式 + 查询式 |

两站全量基线（便于对照数字）：

| 项 | 巨浪 | 芒果 |
|---|---|---|
| `<list>` 属性 | `page="1" pagecount="17663" pagesize="20" recordcount="353246"` | `page="1" pagecount="4479" pagesize="20" recordcount="89564"` |
| id 形态 | 18 位（如 `630919202483470340`） | 5 位（2,796–94,392） |
| 线路名 | `jlm3u8`（m3u8）/ `jlplayer`（网页解析） | `m3u8` / `mgtv`（网页解析） |

结论：**官方源码是能力上限，站点部署版本才是实际边界**。接入任一新站点，先跑第八节的自检命令，逐项确认 `h / year / isend / from / pagesize / sort_direction` 是否真生效，再决定功能开关。

## 七、与 vibox 当前实现的对照（按官方设计给出改造点）

### 7.1 参数使用面

| 官方参数 | vibox 是否使用 | 建议 |
|---|---|---|
| `ac` | 仅 `list` / `videolist` | 改用官方主名 `detail`（`videolist` 是历史别名，长期不保证） |
| `ids` | 仅详情请求 | 保持；增加“判空不发” |
| `t` | ✅ | 保持；补“`t` 被 `typefilter` 忽略 → 结果变全量”的兜底判断 |
| `wd` | ✅ | 保持 |
| `pg` | ✅ | 保持 |
| `h` | ✘ | 可加“最近更新”频道（`?ac=detail&h=24`） |
| `from` | ✘ | 可加线路选择（`?ac=detail&from=<线路>`） |
| `pagesize` | ✘ | 站点支持时提高吞吐（20 → 50/100），并回读校验 |
| `year` / `isend` | ✘ | 可做筛选器（需按站点实测） |
| `sort_direction` | ✘ | 需要“最早优先”时使用 |
| `at` | 靠路径 | 保持路径式 |

### 7.2 请求次数（最重要的一条）

vibox 当前流程是 **2 次请求**：`ac=list` 拿列表 → 再 `ac=videolist&ids={整页}` 拿封面。

按官方设计，`ac=detail&t=&wd=&pg=` 一次就能返回整页**含 `pic` 与 `dl`** 的完整数据：

| 方式 | 请求数 | 传输量 | 前端处理 |
|---|---|---|---|
| 当前（list + 详情批量） | 2 | 4,734 B + 138,707 B | 需要按 id 合并封面 |
| 官方（detail 整页） | 1 | 142,761 B | 直接可用，无需合并 |

传输量接近，但省一次往返、少一次 id 拼接与失败点；且 `ids` 拼接过长（20 个 18 位 id）在部分站点会被 URL 长度限制。

### 7.3 解析层必须修正的 5 处（官方格式已确证）

| # | 格式事实 | vibox 现状 | 修正 |
|---|---|---|---|
| 1 | 分页 4 字段是 `<list>` 的**属性** | 按子元素 `<page>` 解析 | 改为读属性 `@page` / `@pagecount` / `@pagesize` / `@recordcount` |
| 2 | 分类 id 是 `<ty id="20">` 的**属性** | 按子元素 `<id>` 解析 | 改为读属性 `@id` |
| 3 | 线路名是 `<dd flag="m3u8">` 的**属性** | 按子元素 `<flag>` 解析 | 改为读属性 `@flag` |
| 4 | `id` 无位宽限制（实测存在 18 位 id 的站点） | `u32` | 改字符串（同时避免 JS 精度丢失） |
| 5 | 列表模式不含 `pic`，详情模式才含 | 固定走两次请求 | 改用 `ac=detail` 整页 |

## 八、自检命令

```bash
BASE="https://<资源站域名>/<采集入口>"

# 1) 列表（XML，20 条 + 分类）
curl -s "$BASE/at/xml/?ac=list" | head -c 400

# 2) 详情整页（一次拿到 pic + dl）
curl -s "$BASE/at/xml/?ac=detail&pg=1" | head -c 800

# 3) 分类内搜索
curl -s "$BASE/at/xml/?ac=list&wd=%E6%80%BB%E8%A3%81&pg=1&t=59" | head -c 400

# 4) 最近 24 小时
curl -s "$BASE/at/xml/?ac=detail&h=24&pg=1" | head -c 400

# 5) 只看某条线路
curl -s "$BASE/at/xml/?ac=detail&ids=<id>&from=<线路名>" | head -c 600
```

自检要点：

1. 首字节是否为 `<rss version="5.1">`（若是 `closed` 或鉴权文本，说明站点关闭/限制）；
2. `<list>` 的 4 个分页字段在**属性**上；
3. `<video>` 里 `id` 位数（决定整数类型安全）；
4. 列表模式**没有** `<pic>`，详情模式**有** `<pic>`；
5. `<dd flag>` 中是否存在以 `.m3u8` 结尾的地址（决定能否播放）；
6. 逐项试探 `h` / `from` / `pagesize` / `year` / `isend` / `sort_direction` 是否真生效（不同部署差异很大）。
