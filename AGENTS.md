# AGENTS.md

映盒剧场 (cine-box) — Electron desktop app built with electron-vite, React 19, TypeScript, antd 6 and Tailwind v4. The UI is Simplified Chinese only; comments and UI strings are Chinese.

## Commands

pnpm only (`pnpm-lock.yaml`, CI runs `--frozen-lockfile`):

```bash
pnpm install     # postinstall downloads Electron and rebuilds app deps
pnpm dev
pnpm lint        # eslint --cache .
pnpm typecheck   # typecheck:node + typecheck:web
pnpm build       # typecheck, then electron-vite build → out/
pnpm format      # prettier --write .
pnpm build:win   # also build:mac / build:linux → dist/
```

There is no test suite or test runner. The verification gate is `pnpm lint && pnpm build` (CI does lint, then build, on Node 22 / pnpm 12.15.0).

## Layout

- `src/main` — main process: window, tray, global shortcut, settings, site store, updater; entry `src/main/index.ts`.
- `src/preload` — contextBridge API; renderer-facing types in `src/preload/api.d.ts`.
- `src/renderer/src` — React app; `@renderer/*` alias points here (also configured in `tsconfig.web.json`).
- `out/` is electron-vite output, `dist/` is electron-builder output; neither is source.

Typechecking is split: `tsconfig.node.json` covers `src/main` + `src/preload`, `tsconfig.web.json` covers the renderer plus `src/preload/*.d.ts`. The root `tsconfig.json` only references those two, so `tsc` alone proves nothing.

## IPC contract

Adding a channel takes three edits: `ipcMain.handle` in main, `ipcRenderer.invoke` in `src/preload/index.ts`, and the hand-written global `Api` types in `src/preload/api.d.ts`. Renderer code only ever uses `window.api` / `window.electron`.

## Window and renderer gotchas

- Frameless (`frame: false`) on Windows/Linux, `hiddenInset` + traffic lights on macOS; `TitleBar.tsx` draws its own window buttons only off macOS.
- Windows double-click-to-maximize is implemented in main with `hookWindowMessage` (drag regions don't emit DOM dblclick). Its hit test hard-codes a 44px title bar, 150px brand zone and 222px actions zone — keep those in sync with any `TitleBar` layout change.
- Theme is dual-track: `applyAppearance()` in `theme/appearance.ts` writes `data-theme` and CSS vars on `<html>` before first paint, and `ThemeProvider.tsx` maps the same palette into antd tokens. Style with the existing `--bg` / `--surface` / `--text` / `--accent` vars, not hard-coded colors, or one theme will break.
- Tailwind's `dark:` variant is rebound to `[data-theme='dark']` in `assets/main.css`, not the default `.dark` class.
- CSP in `src/renderer/index.html` is `default-src 'self'`; do remote HTTP in the main process over IPC, not `fetch` in the renderer. The one exception is `img-src`, which also allows `https:` / `http:` so the 视频 page can paint source cover images directly (with `referrerPolicy="no-referrer"` and a letter placeholder when a cover fails).
- Closing the window only quits when `isQuitting` is set; `closeToTray` also controls the tray icon and the `window-all-closed` behavior.
- Overlays stay clear of the 44px title bar: `main.css` offsets `.ant-drawer` and `.ant-modal-wrap` by 44px (and pulls `.ant-modal` back up via `top: 56px`), so a window scrollbar never covers the window buttons, while the masks still dim the whole window including the title bar. Those rules need the `body` prefix to outrank antd's runtime-injected `.ant-modal-root .ant-modal-wrap`. Every modal is also capped at `calc(100vh - 124px)` through a flex `.ant-modal-container` (header/footer fixed, only `.ant-modal-body` scrolls), so don't reintroduce per-modal `maxHeight` in `styles.body`.

## Persistence and updates

- Settings are a plain JSON file at `app.getPath('userData')/app-settings.json` handled by `src/main/app-settings.ts` (no electron-store). `openAtLogin` is re-read from the OS on every read because users can change it outside the app.
- Console sites live in a SQLite database at `app.getPath('userData')/Data/cine-box.db` (the `sites` and `site_categories` tables), opened with Node's built-in `node:sqlite` (`DatabaseSync`, WAL mode) in `src/main/site-store.ts`. The main process assigns the id (`randomUUID()` with dashes stripped) and the ISO timestamps; the renderer only submits name/display/address/format/remark for add/update, and `updatedAt` is refreshed only by `sites:update`. Opening the category dialog returns stored rows and only fetches `ac=list` when the site has none; 「重新获取」 diffs the response against the DB and, after the user picks a mode, applies it incrementally (add/rename only) or fully (also deletes rows missing from the response). Rows are unique per `site_id` + `source_id`, and deleting a site deletes its categories. Back up `-wal` / `-shm` sidecar files together with the `.db`.
- Local video categories live in the same database (`video_categories`: self-referencing `parent_id`, `sort_order` for sibling order, `visible` for whether the category shows on the display side) and are handled by `src/main/category-store.ts`. Both stores share one connection through `src/main/database.ts` (`openDatabase` / `closeDatabase` / `inTransaction`) — do not open a second `DatabaseSync` for the same file. Sibling names must be unique, deleting a category deletes its whole subtree, and `categories:move` takes `(id, targetId, placement)` so the main process — not the renderer — works out the new parent and index; moving a category under its own descendant is rejected (`CYCLE`). Databases created before `visible` existed are migrated in `init()` via `pragma_table_info` + `ALTER TABLE ... ADD COLUMN visible INTEGER NOT NULL DEFAULT 1`, so keep that migration idempotent. `categories:setVisible` only flips the category's own flag and bumps `updated_at` when the value actually changes; hiding is display-side only: the management tree always lists every category, and a hidden parent hides its descendants at read time (renderer `visibleCategoryIds`) without rewriting the children's flags, so re-showing the parent restores each child's own state. Binding and parent selection intentionally ignore `visible`.
- Bindings live in `category_bindings` (`src/main/binding-store.ts`), keyed by `UNIQUE (site_id, site_category_id)` — N:1, so one online category belongs to at most one local category. No names are denormalised: reads join `site_categories` / `video_categories`. The connection sets `PRAGMA foreign_keys = ON`, and cleanup relies on `ON DELETE CASCADE` from `sites`, `site_categories` and `video_categories`, so any new table referencing those must declare cascades or deleting a site/category will leave orphans. `bindings:bind` re-derives `site_id` from `site_categories` and rejects a mismatched pair (`INVALID_INPUT`); binding is upserted so rebinding keeps the row id and only bumps `updated_at` when the target changes.
- Backups live next to the database in `userData/Data/Backups`, written as plain JSON by `src/main/backup-store.ts` (format marker `cine-box-backup`, version 2; version 1 files are still readable and restore with no schedules, camelCase copies of all five business tables). `backup:create` snapshots the DB and refuses to write an empty file; `backup:export` copies a record out through the save dialog so it can be shared; `backup:pick` parses a custom file and returns counts without writing, and `backup:restore` accepts either `{ id }` or `{ path }`. Restore is a full replace in one transaction — it validates every row and reference (ids unique, `site_categories.site_id` and bindings' `site_category_id`/`video_category_id` resolvable, category parents acyclic, schedule sites present), deletes the five tables in FK order, then inserts sites → site categories → categories sorted by depth → bindings → schedules, and it always writes a `-auto` safety backup of the current data first. Any new table must be added to `readState` / `parseBackup` / `applyState` and to `BackupCounts`, or backups silently lose it.
- The binding UI is renderer-only: `Console.tsx` lifts `bindingSite` and switches to 分类, `Categories.tsx` renders two columns (`BindingWorkspace.tsx` on the right) and binds on drop. rc-tree's `TreeNode` calls `preventDefault()` + `stopPropagation()` on `dragover` / `drop`, so an external drag (the online category list) must be handled by native capture-phase listeners on the wrapper — React `onDragOver` on the wrapper never fires. Bind targets are resolved from `data-category-id` on the row, and the internal reorder drag is left to rc-tree (its `onDrop` bails when `dragNode` is missing). In binding mode `.category-body.is-binding` is exactly `calc(100vh - 144px)` tall (标题栏 + `settings-panel-head`, then the page's 44px bottom padding) with `grid-template-rows: minmax(0, 1fr)`, so both columns are always the same height and scroll inside themselves while the page never scrolls: the left tree card fills its column (`.category-body-main` is a flex column) and the right column is a flex column with a non-scrolling `.workspace-head` whose description doubles as the drag hint, `.workspace-groups` being the scroller whose group titles are `position: sticky`. The local category tree starts collapsed and auto-expands only while binding mode is on (an `expandedMode` ref re-applies the policy only when the mode flips, so manual toggles survive normal edits).
- `electron-updater` is disabled unless packaged. To exercise it in dev: PowerShell `$env:CINEBOX_DEV_UPDATE='1'; pnpm dev` (else `CINEBOX_DEV_UPDATE=1 pnpm dev`), which reads `dev-app-update.yml`. Draft releases are invisible to the updater.

## Release

Use the `.agents/skills/cine-box-release` skill for 发版. Constraints the CI `guard` job enforces:

- Git tag `vX.Y.Z` must equal `package.json` `version`.
- `CHANGELOG.md` must contain the exact heading `## 映盒剧场 vX.Y.Z`; that section becomes both the GitHub release notes and the in-app update notes.

Tag push builds four platforms and uploads to a **draft** Release; publishing is a manual `gh release edit vX.Y.Z --draft=false`. Do not set `publish.releaseType: release`, rename `latest*.yml` / `*.blockmap`, or build both macOS arches in one job (see the skill for why).

Both macOS jobs write the same `latest-mac.yml`, so they hand their copy to the `mac-index` job, which merges both arches into one `files` list (`scripts/merge-mac-update-index.mjs`) and replaces the file on the draft. Without that step `latest-mac.yml` lists only the arch that finished last, and `MacUpdater.filterFilesForArch` makes Apple Silicon install the Intel build. Keep the merged index in mind when changing the macOS matrix.

## Conventions

- Branch `master`; Conventional Commits, e.g. `feat(updater): ...`, `fix(renderer): ...`, `chore: release v1.0.1`.
- Prettier: no semicolons, single quotes, print width 100.
- `build/icon.svg` is the brand source; keep `src/renderer/src/assets/logo.svg`, `build/icon.{png,ico,icns}` and `resources/icon.png` in sync when it changes.
- `docs/采集接口参数说明.md` documents an external XML collection API; `src/main/video-collect-parser.ts` and `src/main/video-collector.ts` implement it.
- Video cache is a separate `userData/Data/video-cache.db` (never the business DB): `videos` / `video_sources` / `videos_fts` / `collect_progress` / `collect_logs` / `cache_sites`. Detail bodies are JSON files under `userData/Data/videos/<siteId>/<safeSourceVideoId>.json`; SQLite only stores the `video_sources.detail_*` index. `src/main/video-cache-store.ts` owns the connection, `video-detail-cache.ts` reads index-first and fetches on miss, and `video-collector.ts` runs a single in-memory queue shared by manual and scheduled runs. `collect_schedules` lives in the business DB so `videos:clear` keeps schedules; `collect_logs` and progress are cleared with the cache. Adding/removing a site cancels its collection and removes its cache rows and detail directory. Collection only writes the list index unless `cacheDetail` is set (manual 采集 or the schedule's `cache_detail`, both switches default to checked; the manual dialog remembers the last choice in `localStorage` under `collect-manual-cache-detail`, while each schedule keeps its own saved value). Because the page request is already `ac=detail`, the parsed page carries full intro + play lines, so the collector feeds them to `details.warmFromPage()` and writes the detail file without any extra request; only page entries whose intro and play lines are **both** empty (a deployment whose whole-page mode omits detail fields) go to `details.warm()`, which still fetches in batches of 10 ids and never fails the run. `warm()` remains the on-demand path, so don't wire the page shortcut into `read()`/`refresh()`. Each page now logs its own timing split (列表 / 写库 / 详情, plus 本页直接 vs 补抓 for details) and the 暂停 / 完成 / 开始全量替换 lines carry the page-phase total, which is how the 11 → 1 round trips per page change is verified. `collect_logs` writes are queued, never synchronous on the collection path: `createCollectLogStore().append()` only pushes into an in-memory array and schedules a `setImmediate` flush that inserts the batch in one transaction (then trims every 100 written rows) and only afterwards emits each row to the renderer, so `append()` returns `void` and the page loop never waits for SQLite; `flush()` is called before `videoStore.close()` on quit and at the top of `videos:logs:list` (a read must see the newest warnings), while `videos:clear` and `videos:logs:clear` drop still-queued rows so they cannot be written back after a clear — a flush that throws (DB closed / rebuilding) still emits to the UI instead of losing the line. Page size is history-first, probed only as a last resort: some deployments silently ignore `pagesize` (the official cap is 100) and keep returning their configured 20, so the resolved size is remembered — `collect_progress.page_size` (seeded by `prepareTask`, then overwritten by every response's real `pagesize`/`limit`) and `collect_schedules.page_size`. `videos:collect:start` / `videos:schedules:save` reuse that stored value (same mode + range row first, else any row for the site, else the plan's own value) with **no** network request, and only when there is no history at all do they call `src/main/video-collect-probe.ts` (`ac=list&pg=1&pagesize=100`, 6s timeout / 1 retry, no `ids`); the task then requests the resolved value (`buildUrl`) and the 进度 card shows 每页 N 条 before the first page lands, together with the server-reported record total (`collect_progress.record_count` → `共 N 条`, formatted by `formatCount()` in `utils/format.ts` so six-digit totals stay readable). `videos:clear` wipes progress, so the next task after a cache clear probes again. A failed probe is never fatal (falls back to 100), an already live task skips the probe, and a disabled plan save does no network. `collect_schedules.page_size` is 0 when unknown and is migrated idempotently like the other late columns and carried through `backup-store`'s schedule rows, while the inline 继续 / 重新 buttons on the 进度 card pass the row's already-known `pageSize`. `collect_schedules` supports two timing modes: `timing = 'interval'` (every `interval_minutes`) and `timing = 'daily'` (every day at `daily_time`, 24h `HH:mm`, local time). `next_run_at` is computed by `src/main/schedule-time.ts` (`nextRunAt()`) both when a plan is saved and after each run, so a daily plan whose time already passed is caught up once on the next start. The 间隔 field is only rendered for `timing = 'interval'`, and antd unmounts that `Form.Item` when the user switches to 每天固定时间 — `validateFields()` only returns currently mounted fields, so `interval_minutes` must be treated as optional for a daily plan: the renderer re-reads it from the form store (`getFieldValue`) and `collect-schedule-store.save()` keeps the stored value (default 360) instead of returning `INVALID_INPUT`, which is what made 每天固定时间 impossible to save. `cache_detail`, `timing` and `daily_time` are later additions to `collect_schedules`, migrated idempotently in `collect-schedule-store.init()` via `pragma_table_info`; backups without those fields restore as off / interval. 控制台「视频」页 (`Videos.tsx`) is an antd `List` (`itemLayout="vertical"`, cover in `extra`) over that cache: `videos:list` takes `page`/`pageSize` (10 per page, total from a second COUNT query) plus `keyword` and `visibility` (`all` / `shown` / `hidden`), and that `total` is also what the page header prints as `共 N 个视频` — so the header number is the **filtered** count, not the whole library. `videos:detail` fills the drawer (sources + play lines) and the edit modal's cover choices. The list handler enriches every row with `localCategoryPaths`, resolved from `category_bindings` via `bindingStore.pathsForSourceCategories()` plus `videoStore.listSourceCategories()`, so the meta line can show the bound local category alongside the raw `vod_class`. Row spacing is overridden in `main.css` with `.video-list .ant-list-items .ant-list-item …` selectors: antd's `.ant-list-vertical .ant-list-item .ant-list-item-meta` is three classes deep and sets a 16px bottom margin plus a 16px/1.5 title, which otherwise leaves the 来源 line floating far from both the title and the intro. The video name is a `<button class="video-title-text">` that opens the 详情 drawer (same entry as the cover and the 详情 action button); it keeps the title's font size/weight and ellipsis from `.video-title-text`, so restyle it through the `button.video-title-text` reset instead of adding button defaults. The 详情 Drawer pins everything above the source list: `styles.body` is `padding: 0` plus a non-scrolling flex column, `.video-detail` is the flex child filling it, `.video-detail-sticky` holds the cover / title / 简介 and the 「来源与播放线路」 label (own 16px 18px padding, bottom border, `--elevated` background; 简介 is clamped to 5 lines by `-webkit-line-clamp: 5` so the fixed area stays a predictable height), and `.video-detail-scroll` is the only scroller — so don't reintroduce body padding on that Drawer or a `max-height` on the list, and put new detail fields on the correct side of the divider. Each source in that list is a `SourceCard` (module-level component, so its `useState` resets when the drawer content is destroyed): collapsed by default, the whole head row is a `<button>` with `aria-expanded`, a `RightOutlined` caret that rotates 90° (`is-open` on `.video-source`), and a `N 条线路 · M 集` summary so a collapsed card still says something — add new per-source info to the head, and don't put a click handler on `.video-source` itself. Episodes are `<button class="video-episode">` and clicking one copies its play URL (`copyText()` tries `navigator.clipboard.writeText` first and falls back to a hidden textarea + `execCommand('copy')`, since Electron leaves clipboard permissions at their default) with an antd `message` toast from `App.useApp()` — the `还有 N 集` chip stays a `<span>` because it is not clickable. Edits live in `video_edits` (same cache DB, one row per video): NULL columns mean "use the collected value", `hidden` defaults to 0 = visible on the display side. `videos:update` only writes the fields it is given, rejects a `pic` that is not one of that video's source pics (`INVALID_PIC`), and an empty string clears the override; the name is a merge key and is intentionally not editable. `listVideos` / `getVideoDetail` read through `COALESCE(e.*, v.*)` so overrides survive collection (`recomputeVideo` only touches `videos`). A `video_edits` row is deleted when the video is deleted, and `videos:clear` rebuilds the cache DB, which drops edits along with the rest of the cache.
- 控制台「日志」(`Logs.tsx`) 和视频列表一样用**页面**滚动条：`.log-list` 不再设 `max-height` / `overflow-y`，而是由 `.page` 滚动，所以滚动条在窗口右缘、列表下方不留空白；服务端保留策略的说明（最多 5000 条 / 30 天、清空视频缓存时一并清空）挂在头部「最近 N 条」右边，底部不再有说明行。标题行与筛选工具条包在 `.log-sticky` 里整体 `position: sticky; top: 0` 吸顶（内层 `.settings-panel-head` 在这个页面上置成 `static`，避免两层 sticky 与双份背景），因此「自动滚动」滚的是 `.page`（`closest('.page')`）而不是列表本身；行样式是 grid 单行（时间 / 级别 / 站点 / 模式 + 正文吃剩余宽度、单行截断、完整内容在 `title` 里），新增字段请沿用这套列结构，窄窗口（< 900px）会让出「模式」列。
- 控制台「概览」(`Overview.tsx`) is the default console section and adds no IPC: one `Promise.all` reads `sites:list`, `categories:list`, `bindings:counts`, `videos:stats`, a `videos:list` page with `visibility: 'hidden'` (only for its `total`), `videos:capacity`, `videos:schedules`, `videos:progress` and one `videos:logs` batch (`since` = 24h ago, 100 rows). It renders four clickable stat cards (视频库 / 站点与分类 / 定时采集 / 缓存占用, each navigating through `onNavigate`), a 最近采集 + 定时计划 two-column pair, and a 最近 24 小时异常 block that only appears when that log batch contains warn/error rows; an install with no sites gets a three-step onboarding card instead. `videos:onProgress` patches the recent list in place, and a `done` / `error` event triggers one silent reload so counts and cache size stay current. `ConsoleSection` lives in `src/renderer/src/types.ts` and `Console.tsx` renders the sections with an exhaustive `switch` (the old `console-empty` placeholder branch and CSS are gone). Collect status text/colour, `formatInterval` / `formatScheduleTiming`, `siteLabel`, `COLLECT_ERRORS`, `collectProgressKey`, `isResumableStatus` and `manualCacheDetail()` are shared from `src/renderer/src/utils/collect.ts` by `Progress.tsx` and `Collect.tsx` too — don't reintroduce copies. A `paused` / `error` progress row can be resumed straight from its 进度 card (`继续采集`) or restarted (`重新采集`, i.e. `restart: true` → `prepareTask` resets page/counters); the 采集 dialog offers the same two choices when the selected mode + fetch range already has a paused/error row (`restart` is a renderer-only decision, the collector still refuses a live duplicate with `ALREADY_QUEUED`). Resuming keeps `page`, counters and `started_at` (full-replace token), and `runTask` clears `finished_at` on start so the card stops showing the old end time. The progress card has no dialog to ask about detail caching, so those inline actions reuse the last manual choice (`manualCacheDetail()`). Row timestamps use `formatShortDateTime` (drops the current year) and future plan times use `formatUpcoming` (今天 20:00 / 明天 …); both live in `utils/format.ts`.
- 控制台「采集」(`Collect.tsx`) 每个站点一张卡片，meta 固定三行（采集 / 计划 / 定时）。定时那一行常驻：没配计划时和「计划」一样显示横线（`定时：—`），配了则显示 `formatScheduleTiming()` 的结果，后面按情况追加 `· 每页 N 条` 与 `· 含详情缓存`。卡片动作只有 采集 / 定时 两个按钮，进度统一走头部的「查看进度」，卡片上不要再加进度入口；任务处于 `queued` / `running` / `replacing` 时额外出现一个带「取消」文字的 danger 按钮（`StopOutlined`），点击走 `videos:collect:cancel` 把任务停在断点，之后可以续采。
